# F12-2 · Akceptacja briefu i przekazanie strategii

## User story

Źródło merytoryczne: AI_Company_Open_Mercato_Proces_v2.xlsx. Sposób opisu: riscore V2. Status oznacza ustalenie zakresu, a nie wdrożenie.

### Status ustalenia

### Nazwa funkcjonalności

Akceptacja briefu i przekazanie strategii

### Definicja

System zapisuje akceptację aktualnej, gotowej wersji briefu przez uprawniony kontakt, bez sprzecznego polecenia zmiany. Historia decyzji pozostaje dostępna. Aktualny zaakceptowany brief i zweryfikowany pakiet analizy pozwalają przekazać zlecenie do strategii w procesie 5.

### Krok procesu

4.6

### ID historii

F12-2

### User story

Jako koordynator analizy chcę odrzucać pozorne lub nieaktualne akceptacje, żeby nie rozpoczynać strategii na podstawie nieuzgodnionego briefu.

### Kryteria akceptacji

1. Zgoda dotycząca starej wersji nie nadaje akceptacji aktualnej wersji briefu.
2. Brak odpowiedzi, samo otrzymanie materiału lub przesłanie załącznika nie są zapisywane jako akceptacja.
3. Odpowiedź „akceptuję, ale zmień…” jest uwagą zgodnie z decyzją G, a nie zgodą na wersję.
4. Decyzja osoby bez potwierdzonego uprawnienia nie uruchamia 4.7; spór o uprawnienie trafia do E.1.
5. Nowa treść nie dziedziczy zgody starej wersji, a historia wcześniejszej akceptacji pozostaje dostępna.

### Podstawa ustalenia

Proces 4.6; Decyzje DEC-AKCEPTACJA; Dokumenty WEW-ZGLOSZENIE; Zasady produktu: Dokumenty. Stara wersja, milczenie i zgoda ze zmianą nie wystarczają do dalszego wykonania.
