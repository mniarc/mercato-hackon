### Definicja

Klient otrzymuje wskazane wersje dwóch osobnych dokumentów wraz z uzasadnieniem i może je zatwierdzić lub skomentować. System zapisuje decyzje uprawnionego klienta po obsłudze przez G; dopiero komplet aktualnych akceptacji otwiera planowanie.

### Krok procesu

5.7

### ID historii

F24-2

### User story

Jako klient chcę, żeby system zapisał, które wersje strategii i tone of voice zaakceptowałem, żeby kolejne materiały powstały dopiero z kompletnej aktualnej pary.

### Kryteria akceptacji

1. Rekord decyzji wskazuje uprawnioną osobę, czas, źródło oraz osobne identyfikatory wersji strategii i TOV.
2. Zapis jest możliwy po dyspozycji 5.6, pozytywnym QA pary i potwierdzeniu, że brief bazowy nadal obowiązuje.
3. Częściowa akceptacja jednego dokumentu pozostaje w historii, lecz nie uruchamia planowania bez gotowej zaakceptowanej pary.
4. Akceptacja nieaktualnej wersji lub odpowiedź z żądaniem zmiany nie otwiera bramki; wyjaśnienie albo poprawa wracają właściwą ścieżką przez G.
5. Zgoda obejmuje wyłącznie pokazane dokumenty i nie zatwierdza z góry planu lub postu.

### Podstawa ustalenia

Częściowe akceptacje zachowujemy, ale aktualna zaakceptowana para jest warunkiem planowania. Decyzje: DEC-AKCEPTACJA; Zasady produktu: Dokumenty. Źródło: arkusz Proces, kroki 5.7.
