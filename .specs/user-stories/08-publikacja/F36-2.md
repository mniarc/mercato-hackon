### Nazwa funkcjonalności

Kontrolowana rezerwacja i rozpoczęcie publikacji

### Definicja

Proponowany mechanizm sprawdza wersję, zgodę, dostęp, blokady i wcześniejsze próby, atomowo rezerwuje jedno wykonanie i ponownie atomowo sprawdza warunki przy przejściu do wysyłania. Adapter wysyła dokładnie zatwierdzony tekst; cofnięcie po rozpoczęciu wymaga ustalenia rzeczywistego wyniku.

### Krok procesu

8.4

### ID historii

F36-2

### User story

Jako operator integracji chcę atomowo zarezerwować jedno wykonanie publikacji, żeby równoległe uruchomienia nie wysłały dwóch wiadomości.

### Kryteria akceptacji

1. Po spełnieniu bramek system atomowo zapisuje jedną rezerwację z unikalnym ID próby, zamówieniem, wersją postu i dokładnym celem.
2. Równoległe dopuszczenia dla tej samej realizacji nie uzyskują dwóch ważnych rezerwacji.
3. Istniejąca wykonana publikacja lub próba o wyniku nieznanym uniemożliwia uzyskanie nowej rezerwacji.
4. Rejestr zachowuje historię prób i przyczyn blokad; rezerwacja sama w sobie nie jest dowodem wysyłki ani sukcesu.

### Podstawa ustalenia

8.4 wymaga atomowej rezerwacji pojedynczego wykonania i sprawdzenia poprzednich prób. Rejestr wykonania jest wskazany w procesie, lecz nie ma osobnego ID dokumentu w katalogu. Źródło: arkusz Proces, kroki 8.4.
